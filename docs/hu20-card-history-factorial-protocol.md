## Candidate history schema, before density or strength outcomes

Preflop preserves the full baseline key and ordered history. Postflop retains
all current-street tokens from the baseline ordered encoder, in their original
order, with actors, existing raise-size labels and all-in markers unchanged.
"Exact" means preservation of that existing representation, not a new change
to exact-chip sizing. Earlier actions are replaced by these public features:

- preflop line: zero/one/two/three-or-more raises, any voluntary call, last
  aggressor relative to the button;
- last aggressor (or none) on each completed postflop street;
- current street-start pot band in BB: thresholds 2, 4, 8, 16, 32;
- current street-start effective remaining stack/pot band: .5, 1, 2, 4, 8.

Street-start chips are reconstructed only from public blind/action payments
before that street's BoardDealt event. The current board/card descriptor, seat,
street, folded/all-in flags and menu remain baseline inputs. Versioned artifact
identity prevents silently resuming full history as compressed history.
No changes to observations, game, cards, action menus, sampling or regret math.
The schema and code revision are committed before any density measurements.
No schema adjustment based on strength outcomes; a failed candidate is retained.

## Phase 0: unpaid correctness and starvation gate

First test deterministic keys/menus, hidden-information isolation, rotated seat
identity, preflop equality, current-street token preservation, chip replay and
separation of line/aggressor/pot/SPR boundary fixtures. Test checkpoint identity,
save/load and fresh-process deterministic resume. Original artifacts stay intact.

Run v1-full and v1-compressed from zero for all three fixed seeds, serially,
recording first complete-iteration boundaries reaching 250k/500k/1M/2M nodes.
Retain actual work/overshoot/iteration/attempted discarded work, per-street new
keys and visits, wall/step throughput, RSS, checkpoint/export time and sizes.
No poker payoffs are measured in this phase.

A common, model-independent public-decision corpus is frozen first: 2,048
uniform-abstract-menu deals, both button rotations, root 202610110001. Record
native public traces and the same full/compressed keys at every decision.
Report both unique-key and encounter-weighted visit histograms on these exact
common decisions, including missing keys as zero; also report stored-table
per-street visits. No coverage probe follows a candidate-selected trajectory.

At 2M, the **primary river encounter gate** requires aggregate compressed
median visits ≥ max(2, 2 × full median), and each fraction <10 and <100 visits
at least **5 percentage points lower**. At least two of three individual seeds
must also meet all these thresholds. Report all prefixes/streets regardless of
pass. Do not waive a failed threshold because total key count shrank. Require
all correctness/recovery/isolation/public-separation checks to pass as well.
This gate is a declared materiality convention, not a statistical strength test.
If it fails, retain/report the result and stop before C/D paid training.

Operational M1 bounds: one worker, 6 GiB process RSS, 8 GiB free disk, 30 minutes
per 2M prefix worker, 4M entry safety bound and 250k nodes/300 seconds per complete
iteration. Preserve partial work/checkpoints on failure. The entry bound cannot
be silently changed; resource limits and failed attempts are reported.

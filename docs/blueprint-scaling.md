# Blueprint trainer scaling

The trainer reads the existing regret table without copying it during an iteration. It collects independent root updates, merges them in seat/sample order, validates the complete six-role result, and only then publishes it. A failed root, node/time cap, entry cap, or non-finite update leaves the previous completed iteration unchanged. `step(workers=N)` changes execution only; worker count is not part of the checkpointed learning recipe. The focused test verifies identical serial and two-worker checkpoint hashes after two iterations.

On Linux, process workers inherit the read-only table through `fork`. On macOS, `spawn` serializes the table to each worker; use one worker for the first 16 GiB M4 slice. Worker RSS is recorded per process and summed conservatively with the parent. Shared pages may be counted more than once. The total node cap is checked before publication; parallel roots can do extra bounded work before a failed iteration is discarded. Each root also has the configured node/time cap. Measure aggregate memory and actual throughput on RunPod before paying for many AWS CPUs.

Training checkpoints are now deterministic gzip JSON Lines: one metadata line followed by one line per abstract information set. Saves and loads stream entries instead of materializing the whole serialized table. Atomic replacement keeps the previous checkpoint if a new write fails. The first pilot's older single-document checkpoint remains readable. Inference exports are still separate and are built at a completed run; their memory cost has **not** been calibrated for a large table.

`scripts.train_blueprint` now accepts `--workers`, `--checkpoint-seconds` (default 1800), `--max-wall-seconds`, `--max-rss-gib`, and `--min-free-gib`. It saves after the first completed iteration, at the wall-clock cadence, on a clean stop at an iteration boundary, and at the requested final iteration. `iterations.json` records nodes/second, peak parent RSS, conservative parent-plus-worker RSS, and trained/fallback decisions by street. `checkpoints.json` records each save's duration, size, and hash. A capped run exits with code 2 and a resumable checkpoint; final export and arena evaluation run only when the declared iteration target is reached. Resource guards are checked between iterations, so leave headroom for one full iteration and checkpoint save.

The next task is to freeze a useful six-player M4 slice plan and run it with one worker, a roughly 10 GiB RSS guard, an explicit disk guard, and a one-hour wall cap. Its result determines whether more training fits the M4 or requires the bounded RunPod memory/worker check in the [training roadmap](blueprint-training-roadmap.md).

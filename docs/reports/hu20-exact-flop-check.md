# HU20 exact flop check: M4 validation and resource stop

**2026-10-02 — draft [PR #145](https://github.com/dberweger2017/deepcfr-texas-no-limit-holdem-6-players/pull/145).**
The external solver integration, compact card/policy export, equity previews,
profile projections, per-target BR measurements and monitoring work on the
validated fixtures. **The real experiment has not run.** All three real
preflight roots exceed M4 memory, including the declared cap-three fallback.
There is consequently no evidence here to choose H1, H2, H3 or H0. No training,
model promotion, paid compute or automatic merge occurred.

## Real preflight

The first B500M current export is hash-verified. Root ranges are computed by
`public_ranges`; only exactly zero-weight hands are removed. The public flop is
6s 3d Jc, generated by the frozen fixture seed, with native preflop lines
call/check, min/call and min/min/call. BB = 100 chips; root pots are 2/4/6 BB and
remaining stacks 19/18/17 BB respectively. Betting lines are exported by replaying
the native engine, not by approximating them with solver bet-size syntax.

| Spot | Positive OOP/IP holdings | Native public nodes | Native compressed strategy lower bound | Native node-arena lower bound |
| --- | ---: | ---: | ---: | ---: |
| Limped | 836 / 719 | 114,289 | 716.02 GiB | 14.91 GiB |
| Min-raised | 660 / 763 | 68,309 | 389.59 GiB | 8.87 GiB |
| Three-bet | 290 / 646 | 49,259 | 183.93 GiB | 6.37 GiB |

The pinned solver allocates its node arena inside `with_config`, before
`memory_usage()` becomes available. The native cases were rejected before that
allocation: the arena alone exceeds the measured 6 GiB initial budget. These
are **provable lower bounds**, not values returned by `memory_usage()`. The
rainbow flop has distinct suit ranksets, so the pinned source cannot identify
turn/river suit orbits; its ordered river multiplier is 2,352. The strategy
bounds omit extra storage and metadata. Sixteen-bit compression cannot reduce
the arena or make the native cases fit.

Cap three retains legal jams at every street. These smaller arenas permit the
actual API memory probe, with **no strategy allocation**:

| Spot, cap three | Public nodes | API uncompressed | API compressed | Solver's measured peak RSS |
| --- | ---: | ---: | ---: | ---: |
| Limped | 15,693 | 193.24 GiB | 97.64 GiB | 2.22 GiB |
| Min-raised | 10,073 | 112.42 GiB | 56.86 GiB | 1.42 GiB |
| Three-bet | 6,907 | 50.83 GiB | 25.86 GiB | 0.97 GiB |

The ladder is exhausted: compression is insufficient, ranges already omit
zeros, and cap three is still oversize. No capped equilibrium or removed-reach
audit is claimed. **Solve-to-target time, equilibrium residual and main wall
time are unavailable for these real spots.** A smaller Set B would reduce total
work, but would not resolve per-spot memory. A larger host or a different exact
solver memory design needs a separately approved resource comparison and
protocol amendment; no rental has been proposed as already authorized.

The measured admission rule is min(6 GiB, floor(80% reclaimable GiB)), with
reclaimable = free + inactive + speculative pages. It admitted 6 GiB initially
and 5 GiB on the repeat. One solver ran at nice 10 with two Rayon threads after
the idle-core/process snapshot. The initial machine swap was **745.38 MiB** and
remains **745.38 MiB** after the fixtures and exports. Other jobs and the existing
TensorBoard server were left running. Aggregate preparation RSS peaked at
3.07 GiB during the complete descriptor/equity export, which took 34.44 seconds.
Fast memory probes also record the solver's own `getrusage` peak, since a polling
watchdog can miss a sub-second arena allocation.

Evidence: [`preflight.json`](hu20-exact-flop-check-artifacts/preflight.json),
[`instrumented repeat`](hu20-exact-flop-check-artifacts/preflight-with-self-rss.json)
and [`export resources`](hu20-exact-flop-check-artifacts/fixture-export-resources.json).
Each raw request, response, process snapshot and attempt remains on the M4.

## Validation and complete export fixture

| Gate | Retained result |
| --- | --- |
| K | 100,000 production/factored-key comparisons; zero mismatches across three pot types, all postflop streets, holdings and runouts |
| V1 | Every declared fixture and preflight betting line/action matches the solver tree; zero mismatches |
| V2 | 1,900 terminal samples: 600 river, 300 tiny-SPR flop and 1,000 short-SPR full-flop; zero integer-chip settlement mismatches; maximum float error below 0.00008 chip |
| V3 | Both responder seats on limp and three-bet river fixtures agree with native `profile_quality` within 0.000001 BB |
| V4 | All three locked-policy EVs are inside their 20,000-deal native 95% intervals; 60,000 independent deals total |
| V5 | River residuals 0.18743% and 0.13331% pot; full flop fixture residual 0.0006314% pot; all meet the 0.2% target |

The full flop fixture is an equal-stack HU20 native root after 18 minimum
preflop raises and a call: 38 BB pot, 1 BB remaining per player, four artificial
holding-range entries per seat. Its full native tree has 25 public nodes.
All 9,608 legal board/node contexts are locked from the actual frozen Python
policy. The solver's physical-seat-zero EV is −3.107385 BB, within native Monte
Carlo **−2.8593 [−3.12650, −2.59210] BB**. Subtracting half the root pot reconciles
the equal-investment HU20 payoff with net chips from the original stack. This
estimate is conditional on the artificial root, not an unselected policy win rate.

A separate 30 BB pot / 5 BB remaining fixture covers 1,177 native public nodes,
ordinary betting across all streets and early all-in fixed runouts. Its 1,000
terminal checks comprise 489 folds and 511 showdowns. The external payoff-query
helper descends the all-in chance subtree to the specified final board; this
tests a realized settlement, rather than comparing it with an all-in node's
expected EV. See [`full-flop payoffs`](hu20-exact-flop-check-artifacts/full-flop-payoffs.json).

The separate exporter produces all **2,402 boards** (flop + 49 turns + 2,352
ordered rivers), **1,176 root holdings**, byte descriptor arrays with blocked
sentinel 255, native line templates and deduplicated descriptor/policy tables.
Equity features exhaust 1,176 unordered final boards, share their values across
both turn/river orders, build 20-bin histograms, cluster K=50/200 per street and
use pooled river equity quantiles. All of that export ran under the watchdog;
the NPZ arrays remain private inputs on the M4. See the
[`hash manifest`](hu20-exact-flop-check-artifacts/fixture-export.json).

An end-to-end profile fixture exercises both-seat blueprint, full-v1,
per-line-v1, eq50 and eq200 locks and best responses, plus the overfold hand/key
tables. Its both-blueprint EV agrees with the V4 solver EV to float precision.
The artificial fixture has 50% blueprint fold versus 0% equilibrium fold at its
two flop bet-facing nodes. **These are software checks, not the selected LBR
overfold result or evidence of the real plateau.** The fixture projection gains
are below 0.001 BB and the equilibrium residual is nonzero; do not use them to
classify the real experiment. Raw fixture metrics are
[`profile-fixture-metrics.json`](hu20-exact-flop-check-artifacts/profile-fixture-metrics.json).

The diagnostic test suite passes **101 tests**, including native replay, exact
uniform equity against an independent exhaustive opponent calculation,
cross-line pooling, blocked holdings, stratified selection, incremental monitor
reads, owned-process cleanup on a gate-failure control and Python/Rust JSON
action-order mapping. The main batch runner is not
launched or qualified by these toy checks; real-root V4 comparisons and resource
admission still have to pass before their numbers count.

The JSON profile runner is a verified fixture integration path. It materializes
profiles in Python; it is not a streaming harness for the hundreds-of-GiB native
trees. That streaming projection/lock path and whole-campaign aggregation remain
to be qualified after a resource design is approved. This limitation does not
change the measured solver memory rejection.

## Frozen corpus, absent main results and interpretation

The [protocol](../hu20-exact-flop-check-protocol.md) fixes all six B500M exports,
selection seeds, population weights, projections, thresholds and stop rules
before any main values. Set A has **214** unique roots behind **273** pinned
selected decisions. Set B has **150** roots, sampled outcome-blind from 10,000
fresh preflop deals, with all pot types and both target positions represented.
There is no overlap between the selected sets. Seeds and complete selection
references are retained in
[`Set A`](hu20-exact-flop-check-artifacts/set-a.json) and
[`Set B`](hu20-exact-flop-check-artifacts/set-b.json).

| H1/H2/H3/H0 decision | Pending; no classification |

The raw v1 LBR panel has **768 hands**, **385 live flop roots (50.13%)** and
**405 dealt flops (52.73%)**, including 20 preflop all-in showdowns outside the
active flop-subgame population. The requested descriptive share would be
0.5013 × mean `e_bp` / approximately 0.65 BB/hand. It cannot be evaluated without
the missing real-root values. The older B100M panel's occupancy and empirical
LBR ranges are not observations of B500M LBR play.

One representation detail corrects the proposal's feasibility claim: v1 also
aliases different public betting lines. In the native retained river fixture,
check/100-chip bet and check/200-chip bet have the same full key for a fixed
holding because `_history` labels both raises `raise-1`. A projection pooled only
at an exact line is therefore a relaxation. The implementation retains that
requested result separately and uses full actual-key pooling for the feasible
v1 result. See the [`actual alias`](hu20-exact-flop-check-artifacts/public-line-alias.json).
The full projection also measures public-history pooling; a large difference
from the per-line result deserves a history audit before a card-only attribution.

Both projections are feasible-policy constructions or relaxations, not the
abstraction's own equilibria. Their losses upper-bound achievable abstract loss;
a high R does not prove that v1 cannot do better. The protocol preserves the
0.7/0.3, 25%/10% and three-point heuristic thresholds with that qualification.
Ranges are taken as given, excluding preflop errors, and per-flop buckets favor
this preview over a global blueprint abstraction. Low per-flop R does not show
that one shared v1 policy can fit every flop simultaneously. Nothing in the resource stop
supports longer training or an abstraction recommendation yet.

## Provenance, failures and monitoring

All **six policy files and three stored-hand files** match the pinned SHA-256
values. The 34 tracked upstream files match the inventory of solver commit
`9d1509fe5077d019825f833eed04b16d342dfda1`, without source edits. The AGPL solver,
Rust harness and Cargo.lock remain outside this MIT repository at
`~/Local/hu20-exact-flop-tool`, retained on both Macs. The inventory records
source, binary and dependency hashes, including the exact ranker and native
engine extension, plus Python, native-package and Rust versions.
The build uses `RUSTFLAGS='-A dangerous_implicit_autorefs'` for the legacy
upstream code's newer-compiler lint; that does not modify the pinned source.
See the initial [`inventory.json`](hu20-exact-flop-check-artifacts/inventory.json),
the latest [`terminal-validation inventory`](hu20-exact-flop-check-artifacts/inventory-terminal-payoffs.json) and
[`upstream inventory`](hu20-exact-flop-check-artifacts/solver-source-inventory.json).

Retained failed attempts and fixes:

- Initial upstream build: newer Rust rejects implicit raw-pointer references.
  Rebuilt with the recorded lint flag and unchanged upstream source.
- Harness metadata-guard build: `Action` has no `Hash`; changed the private
  harness lookup to a canonical debug-string key and rebuilt.
- River validation attempt 01: rsync-preserved source mtime left Cargo using a
  stale binary, so payoff-query records were absent. Touched source, rebuilt,
  recorded the binary hash and reran all gates.
- Flop validation attempt 02: low-level chance children were incorrectly
  addressed with card IDs. Converted representative chance cards to child
  indices; 300 flop terminal samples and V4/V5 then passed.
- Preflight repeat 02: free memory changed the admitted budget, invalidating a
  byte-identical reuse request. Kept the original, wrote a new budget-adjusted
  request and verified its new hash; repeat 03 retains solver peak RSS.
- Public-root replay test: changing a flop without replacing its public board
  event violated `_world`'s replay invariant. Fixed the diagnostic reconstruction
  and verified both button rotations and all four pot types.
- Profile fixture attempt 01: Python/Rust JSON object ordering differed inside
  serialized line identifiers. Canonicalized line keys, retained the original
  compact table, wrote a corrected table and passed the complete lock/projection
  fixture. A regression test checks actual raised lines and action reordering.
- Final inventory command initially referenced an unstaged local manifest path
  on the M4. Copied the pinned manifest into the retained run directory and
  reran the inventory; all input and upstream hashes passed.

All failures remain in `results/flop-check-20261001` on the M4; none disappeared
from a main denominator, because the main run never began. The completed
preflight heartbeat says **resource-blocked; no main run**. Per-spot JSON results
are atomic; retained requests and reference profiles are hash-checked before
reuse. The profile runner locks only the target for BR and records both-locked
EV separately, under a run-wide RSS/swap guard.
